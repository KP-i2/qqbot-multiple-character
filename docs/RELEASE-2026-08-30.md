## 一、更新日志

### 1. 前端 Dashboard

#### 1.1 统一轮询调度器（性能 · 省请求）
**背景**：原实现有 3 个散落的 `setInterval`（`checkHealth` 30s、`loadDashboardStatus` 30s、`refreshWsHealth` 5s），各跑各的，页面隐藏时仍在后台空转请求。

**改动**：
- [core_shared.js](../qqbot/dashboard/static/js/core_shared.js) 新增 `schedulePoll()` 统一调度器：单一 2s 主时钟驱动所有周期任务，各自维护执行间隔
- 页面隐藏（`document.hidden`）时**自动暂停全部轮询**；切回前台立即补刷一次
- [init.js](../qqbot/dashboard/static/js/init.js) 改为 `schedulePoll(checkHealth,30000)` / `schedulePoll(loadDashboardStatus,30000)` / `schedulePoll(refreshWsHealth,5000)`，保留首屏立即刷新一次的原有行为

**收益**：切后台省掉全部周期 API 请求；轮询统一管理，后续加任务一行注册。

#### 1.2 可访问性（无障碍）
- **蒸馏 Modal**（[skills_batch.js](../qqbot/dashboard/static/js/skills_batch.js)）：
  - `Escape` 键关闭
  - `Tab` 焦点圈定在弹窗内（focus trap）
  - 关闭后焦点恢复到触发按钮
- **主题下拉**（[themes.js](../qqbot/dashboard/static/js/themes.js)）：
  - `Escape` 键关闭
  - `aria-expanded` 状态随开关同步
- **语义增强**（[index.html](../qqbot/dashboard/static/index.html)）：
  - 状态 pills / WS badge 加 `role="status" aria-live="polite"`（读屏软件播报服务状态变化）
  - 蒸馏 Modal 补 `role="dialog" aria-modal="true" aria-labelledby`
  - 主题按钮补 `aria-haspopup="true" aria-expanded`

#### 1.3 CSS 收口（文件精简 7→6）
**背景**：`tweaks.css` 是早期"最后加载 + 大量 `!important`"的增量覆盖层，且与基础文件存在大量重复定义，长期堆叠难维护。

**改动**：删除 `tweaks.css`，271 行增量规则按用途分区块并入对应文件，**最终视觉零变化**：
| 并入文件 | 内容 |
|---|---|
| [layout.css](../qqbot/dashboard/static/css/layout.css) | header 渐变 / KPI 玻璃质感 / card 内边距 / 花名册 7 列 / tabs / 动效 stagger |
| [base.css](../qqbot/dashboard/static/css/base.css) | countUp 关键帧 / 滚动条 / `::selection` / `prefers-reduced-motion` |
| [components.css](../qqbot/dashboard/static/css/components.css) | 按钮光泽与 ripple / 输入框 focus / 表格 hover / 空状态 / toast |
| [help.css](../qqbot/dashboard/static/css/help.css) | 帮助文档空状态装饰 |

> 注：头像图片原本就带 `loading="lazy" decoding="async"`，无需额外改动。

### 2. 后端 Dashboard

#### 2.1 P1 性能两项
- **`/api/health` 复用状态缓存**（[routers/process.py](../qqbot/dashboard/routers/process.py)）：
  原实现每次请求都直接跑 `get_napcat_status` + `get_nonebot2_status` 做**全进程遍历**（前端 30s 轮询 + WS 每 5s 推送都在打这个口）。现改为复用 `get_all_status` 的 **5s 缓存**，高频 psutil 扫描消失。
- **turns 历史改尾部读取**（[routers/turns.py](../qqbot/dashboard/routers/turns.py)）：
  原 `_read_turns_history` 每次 `readlines()` 整个 jsonl（可达上万行）再逐行 `json.loads`。新增 `_tail_lines()` 只从**文件尾部回读**最近 `limit*3+10` 行，聚合逻辑与原来完全一致。

#### 2.2 P2 低成本加固
- **`/api/llm-providers` mtime 缓存**（[routers/settings.py](../qqbot/dashboard/routers/settings.py)）：
  前端 30s 轮询一次，原实现每次都重解析 `.env` 文本 + `runtime_settings.json`。现按文件修改时间（mtime）缓存，配置未变直接返回缓存。
- **Token 常量时间比较**：
  HTTP 中间件（[main.py](../qqbot/dashboard/main.py)）与 WebSocket 校验（[routers/ws.py](../qqbot/dashboard/routers/ws.py)）改用 `secrets.compare_digest`，消除 timing attack 风险。
- **搜索健康写盘限频**（[config.py](../qqbot/plugins/char_chat/config.py)）：
  搜索源连续失败时原本**每次失败都写盘** `search_health.json`，现加 5s 限频。

#### 2.3 P3 路由拆模块（架构重构）
**`main.py` 从 1384 行 → 139 行**，45+ 路由按业务拆分到新 `dashboard/routers/` 包，逻辑零变化：

```
qqbot/dashboard/routers/
├── __init__.py      # 包标记
├── _shared.py       # 共享路径常量 / 安全校验 / token 常量时间比较
├── process.py       # 进程管理 / /api/health / Dashboard 自管理 / snowluma 日志 SSE
├── turns.py         # 对话流水历史 + SSE 推流
├── corpus.py        # Cookie / 微博 / QQ / 文本语料 / 推特抓取 / 语料蒸馏
├── skills.py        # Skill CRUD / 编辑 / 蒸馏 / 头像 / AI 特征整合
├── settings.py      # 运行时参数读写 / LLM Provider 状态
├── docs.py          # 帮助文档（README + docs/*.md）
├── logs.py          # 日志查看
└── ws.py            # WebSocket 实时状态推送
```

#### 2.4 顺手修复
- **twitter 抓取子进程路径残留**（[routers/corpus.py](../qqbot/dashboard/routers/corpus.py)）：
  原代码引用 2026-07-23 已废弃的旧 venv 路径 `skill_qqbot/Scripts/python.exe`（文件已不存在，靠 fallback 才正常工作）。现直接用当前解释器 `sys.executable`。

#### 2.5 全栈检查补充修复（第二轮，均已实测）
- **monitor.py 性能**（[monitor.py](../qqbot/dashboard/monitor.py)）：
  - `check_port_open` 由 socket connect 改为 psutil LISTEN 检测：连未监听端口时原要等满 1s 超时 → **毫秒级**（500 倍）
  - `get_all_status` 里 `get_napcat_status` 原被调用两次（snowluma + napcat 字段）→ 只调一次复用
  - 综合效果：`get_all_status` 冷启动 **7.5s → 3.9s**，缓存命中 0s
- **kpi.js 鉴权修复**（[kpi.js](../qqbot/dashboard/static/js/kpi.js)）：
  LLM 状态卡原用裸 `fetch('/api/llm-providers')` **不带 token header**，开启鉴权后必 401（日志可见 `401 Unauthorized`），KPI 卡显示 "-"。改为 `safeFetch`（自动带 `X-Dashboard-Token`）。
- **静态资源缓存策略**（[main.py](../qqbot/dashboard/main.py)）：
  `/static/*` 加 `Cache-Control: no-cache`（保留 ETag 校验）。此前静态 JS/CSS 无缓存头，**前端改版后浏览器可能一直用旧文件**；加后每次 ETag 校验、改版立即生效。
- **setup_snowluma.bat 路径修复**（[setup_snowluma.bat](../scripts/bat/setup_snowluma.bat)）：
  2 处 `%ROOT%` 路径原指向 `scripts/bat/` 下不存在的目录（`%ROOT%` = 脚本所在目录），导致 snowluma 检测和模板复制失败 → 回退两级到项目根。

## 二、部署说明

### 1. 改动生效方式（按组件区分）

| 组件 | 生效方式 | 是否需要重启 |
|---|---|---|
| **前端静态文件**（index.html / js / css） | FastAPI StaticFiles 直接读磁盘 | ❌ 刷新浏览器即可 |
| **后端路由**（main.py / routers/*.py） | Python 代码改动 | ✅ **必须重启 Dashboard** |
| **Bot 插件**（config.py 搜索健康限频） | Python 代码改动 | ✅ **必须重启 NoneBot2** |

### 2. 标准部署步骤

```
第一步：确认当前服务状态
  Dashboard 正常运行中？NoneBot2 是否在跑？记录当前状态以便回滚对照。

第二步：停止 Dashboard
  方式 A：Dashboard 网页 → 进程管理 → Dashboard 卡片 →「重启 Dashboard」
          （会先 kill 旧进程再拉起新进程，同时生效新代码）
  方式 B（命令行，等价的干净方式）：
    Get-NetTCPConnection -LocalPort 8501 -State Listen -ErrorAction SilentlyContinue |
      % { Stop-Process -Id $_.OwningProcess -Force }

第三步：启动 Dashboard（加载新代码）
  双击 manage.bat  →  自动拉起后台 Dashboard 并打开浏览器 http://localhost:8501

第四步：重启 NoneBot2（仅搜索健康限频那处需要，其余不影响 bot）
  Dashboard → 进程管理 → NoneBot2 卡片 →「重启 NoneBot2」

第五步：验证（见下方验证清单）
```

> 提示：如果之前 Dashboard 一直开着没关，第二步的「重启 Dashboard」就会自动完成旧进程清理 + 新进程拉起，无需手动杀。

### 3. 部署后验证清单

**3.1 后端路由（最关键 — 重构过 main.py，必须确认路由全部挂载）**

PowerShell 一键遍历（换成你自己的 `DASHBOARD_TOKEN`）：
```powershell
$t = '<你的DASHBOARD_TOKEN>'
$urls = @('/api/status','/api/health','/api/dashboard/status','/api/ws-health',
          '/api/snowluma-log/tail','/api/turns/history','/api/cookies','/api/corpus',
          '/api/twitter/cookie','/api/docs','/api/skills','/api/skills/761',
          '/api/avatars','/api/settings','/api/llm-providers','/api/logs','/api/logs/nonebot2.log')
foreach ($u in $urls) {
  try {
    $r = Invoke-WebRequest -Uri ("http://localhost:8501"+$u) -Headers @{ 'X-Dashboard-Token'=$t } -TimeoutSec 15 -UseBasicParsing
    Write-Output ("OK   " + $u + " [" + $r.StatusCode + "]")
  } catch { Write-Output ("FAIL " + $u + " :: " + $_.Exception.Message) }
}
# 预期：全部 OK 200
```

**3.2 鉴权**
```powershell
try { Invoke-WebRequest -Uri 'http://localhost:8501/api/settings' -TimeoutSec 10 -UseBasicParsing | Out-Null
      Write-Output '未带 token → 200（异常！）' }
catch { Write-Output ('未带 token → 401（正常）') }
```

**3.3 前端**
1. 刷新浏览器，Console 无 JS 报错
2. 顶栏 3 个状态 pill + WS badge 正常显示

### 4. 回滚方案

本次改动分三层，可按需回滚：

| 层 | 回滚方式 | 影响 |
|---|---|---|
| **前端**（js/css/html） | 从 Git 恢复旧文件：`git checkout -- qqbot/dashboard/static/` | 立即生效，零风险 |
| **后端路由**（main.py + routers/） | 回退 `main.py` 到拆分前版本，并删掉 `routers/` 目录：<br>`git checkout -- qqbot/dashboard/main.py`<br>`Remove-Item qqbot/dashboard/routers -Recurse -Force` | 需重启 Dashboard |

> 若改动未提交 Git，建议在部署前先备份这 3 层关键文件：
> `main.py`、`routers/`、`static/`、`config.py`

### 5. 风险与注意事项

1. **main.py 重构是最大风险点**：路由拆分后若某个 `@app` 装饰器漏搬，对应 API 会 404。务必执行 §3.1 的全量路由遍历。
2. **turns 尾部读取**：聚合逻辑与原来逐字一致，但只在文件有数据时才有意义（bot 未运行时文件为空，返回 `[]` 属正常）。若发现历史 turn 显示不全，可回退 `routers/turns.py` 中的 `_tail_lines` 实现。
3. **前端 CSS 收口**：理论上视觉零变化；如发现某处样式异常，对照 §3.3 验证，并优先检查 `layout.css` 合并区。
4. **搜索健康写盘限频**：5s 窗口内若进程崩溃，最后几次健康状态可能未落盘（仅影响重启后搜索源健康恢复的粒度，可忽略）。
5. **Dashboard 重启会短暂断开**：正在查看的页面需要刷新；NoneBot2 / SnowLuma 不受 Dashboard 重启影响。
